# Implementation runbook

This is a reconstruction of the lab sequence. Portal labels can change; verify the current Microsoft Defender XDR interface and tenant licensing before implementation.

## 1. Provision the Defender XDR workspace
1. Sign in to the lab endpoint with the authorised lab administrator.
2. Open https://security.microsoft.com.
3. Navigate to Investigation & response → Incidents & alerts → Incidents.
4. Allow workspace/data preparation to complete.
5. If the portal appears stale after provisioning, close and reopen the browser and sign in again.

## 2. Create the Defender device group
1. Settings → Microsoft Defender XDR → Automated response → Devices; follow the device-group management link.
2. Add device group Group1.
3. Set automation level to Full — remediate threats automatically.
4. Set OS condition to Windows 10 and Windows 11.
5. Leave Name, Domain and Tag conditions empty unless required.
6. Skip user access if not in scope; submit and verify Group1 exists.

Production caution: Full automation can trigger remediation without manual approval. Scope the group narrowly and validate the automation level against incident response policy.

## 3. Onboard Client2
1. Settings → Endpoints → Device management → Onboarding.
2. Select Windows 10 and 11; deployment method Local Script.
3. Select Streamlined connectivity.
4. Download and transfer the onboarding package securely to the disposable lab VM.
5. Extract and run the onboarding CMD script as administrator.
6. Confirm Client2 appears under Assets → Devices before proceeding.

Do not commit onboarding packages, tenant-specific scripts, certificates or onboarding blobs to source control.

## 4. Run the controlled simulation
1. Confirm the endpoint is visible and reporting to Defender.
2. Run the authorised simulation script on the disposable test endpoint only.
3. Review the generated incident and endpoint telemetry.
4. Record incident evidence privately; redact tenant and device identifiers before publication.

The source lab reports that AMSI blocked the simulation script. Local protections were temporarily changed on a throwaway VM. Do not repeat this on production endpoints; use approved simulation tooling in an isolated environment.

## 5. Configure the ASR policy
1. Open the Defender portal endpoint security policy workflow or Intune Endpoint security → Attack surface reduction.
2. Create a policy for Windows 10, Windows 11 and Windows Server using the Attack surface reduction rules profile.
3. Name it EndpointPolicy1.
4. Set “Block JavaScript or VBScript from launching downloaded executable content” to Block.
5. Assign the policy to Entra security group sg-Executive.
6. Review and create; validate assignment and device check-in.

## 6. Investigate the incident
1. Open the incident generated by the simulation.
2. Review alerts, attack story/graph, Evidence and device timeline.
3. Identify initiating process, target process and outbound network indicators.
4. Distinguish malicious artifacts from routine background traffic.
5. Record the IOC from the current run; do not reuse an IP from an earlier simulation.

## 7. Create the custom indicator
1. Settings → Endpoints → Rules → Indicators → IP addresses → Add item.
2. Enter the malicious IP observed in current incident evidence.
3. Configure Action: Block execution; Title: Indicator1.
4. Enable alert generation; severity High; category Execution.
5. Scope to all devices only if required and the IOC has been validated.
6. Submit and verify the indicator.

If the required action is unavailable, confirm Custom network indicators is enabled and review current product prerequisites.

## 8. Create the custom detection
Use detections/SuspiciousPowershell.kql, then create a custom detection:
- Name: SuspiciousPowershell
- Frequency: every hour
- Scope: all devices
- Device entity mapping: DeviceId
- User entity mapping: InitiatingProcessAccountObjectId
- Device action: Collect investigation package
- User action: Mark user as compromised

Review automated response implications before enabling outside a disposable lab.

## 9. Live Response and evidence collection
1. Enable Live Response in Settings → Endpoints → General → Advanced features.
2. Open Assets → Devices → Client2 and initiate a Live Response session.
3. Run connections to inspect current network connections.
4. Collect an investigation package and wait for completion in Action center history.
5. Export or download evidence using the method exposed by the current portal build.
6. Isolate Client2 only after evidence collection, where safe and consistent with response procedure.

The source lab returned a CSV export from Action center instead of a ZIP download. This may differ across lab or product builds.
